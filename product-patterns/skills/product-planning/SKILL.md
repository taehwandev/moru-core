# Product Planning

Use for an early product idea, customer problem, opportunity brief or product
proposal that needs a clear outcome, bounded scope and handoff to requirements.
Reuse an existing accepted brief. For an implementation-ready requirement, use
the existing PRD or implementation workflow instead of repeating discovery.

Read `references/current-guidance.md` before drafting. For an artifact used by
later work, also read
`common/skills/product-spec-to-implementation/references/artifact-handoff.md`.

## Process

1. Inspect the request and existing product evidence before proposing scope.
2. Produce a short problem/opportunity proposal with explicit assumptions.
3. Link requirement candidates and open decisions to the existing PRD workflow.

## Stop If

The requested conclusion requires unavailable evidence or a missing material
owner decision. Return the useful draft and identify the blocked conclusion;
do not invent research or approval.

## Verification And Report

Check evidence, scope, testable outcomes and handoff references. Report the
artifact, assumptions, blockers and next owner; a proposal is not delivery proof.
