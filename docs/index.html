Moru is a quiet workbench for coding agents. Moru Core is the open rule set underneath: it tells each agent what to read, which steps a task needs, and what to check before calling it done.

Start with one prompt.

Paste Step 1 into your coding agent inside the target project. Optional Step 2 adds user-level instructions so later sessions find Moru Core on their own.

agent-setup.prompt Required 
Step 1 - Apply Moru Core to this project:
https://github.com/taehwandev/tao-agent-os

Before changing anything, open and read this project's current agent instructions first:
AGENTS.md, CLAUDE.md, CODEX.md, .agents/README.md, CONTRIBUTING.md, task docs,
PRD/ARD docs, equivalent project docs, or explicitly documented local override files.
Do not rely on implicit runtime discovery. Do not claim an instruction file was read unless you actually opened it.

If Moru Core already exists locally or in this repo, reuse that copy.
Do not download, clone, vendor, copy, overwrite, or add another Moru Core root unless I approve after you ask:
"Moru Core already exists locally at . Do you want me to download or pin a new copy anyway, or should I reuse the existing root?"

When updating repo-local instruction files that will be committed, do not write my personal absolute path into them.
Use ${TAO_HOME} for shared local installs or a repo-relative pinned path such as .agents/tao-agent-os.
Full local paths belong only in shell env setup, one-shot prompts, or user-level runtime bridges.

Check user-level runtime bridges, hooks, and permission allowlists with the selected Moru Core root:
~/.tao/bin/tao-hook setup-agent-hooks --check

If the check reports missing bridges, hooks, or permissions, ask for approval to update user-level runtime config, then run:
~/.tao/bin/tao-hook setup-agent-hooks

This is required for Codex, Claude, and AGY to run Moru Core Python wrappers without repeated permission failures. Keep the allowlist narrow; do not broadly allow python3.

If agent instructions or VibeGuard files already exist, ask me how to apply Moru Core before running setup or update.
Only run VibeGuard update if I choose to refresh an existing managed block; otherwise audit current guardrails.
For multi-step work, run ~/.tao/bin/tao-hook start once with --request; it performs routing and preflight. Do not separately repeat workflow list, classify, route, or preflight after it succeeds.
Read every route required_docs entry directly after start and before editing or reviewing. Run the review hook after meaningful edits and the finish hook before final report, commit, release, or handoff.
Direct workflow.py route, agent-preflight.py, and agent-finish-check.py calls are lower-level diagnostic or compatibility fallbacks only; never run them as a second lifecycle.
Missing wrapper evidence or missing route gate evidence is non-compliant.
Use cat gate signals in visible reports: 🐱🟢 SUCCESS, 🐱🔴 FAIL. Do not report any third gate state.
Answer direct questions before starting project work.
Then apply the selected VibeGuard package command with Moru Core as rules,
add only a short routing block,
and continue with my task.

Optional Step 2 - Register a user-level runtime bridge on this machine.

Use this only if I choose the optional setup for better future agent behavior.
Preserve existing personal instructions. Add or update a short managed block; do not replace unrelated user content.

Also run the Moru Core runtime setup check:
~/.tao/bin/tao-hook setup-agent-hooks --check

If bridges, hooks, or permissions are missing, ask for approval to update user-level runtime config and then run:
~/.tao/bin/tao-hook setup-agent-hooks

Keep the permission allowlist narrow: allow only the current Moru Core scripts/*.py files by exact path and suffix-aware runtime matcher, not broad python3.

Update the active user-level file for the runtime I choose:
Codex -> ~/.codex/AGENTS.md
Claude -> ~/.claude/CLAUDE.md
Antigravity -> ~/.antigravity/AGENTS.md
Antigravity SDK/IDE variants -> check ~/.antigravity-ide for the instruction file the active runtime loads.

The bridge must force this behavior:
- Start every task by identifying the current project root.
- If the runtime starts from ~ or another non-project directory, resolve the target with agent-entry.py or project-discover.py before project work.
- If discovery is ambiguous or not_found, ask me for the target project instead of proceeding.
- Before project work, open the project-root instruction file for the active runtime.
- Codex reads AGENTS.md.
- Claude reads CLAUDE.md.
- Antigravity reads AGENTS.md.
- Do not claim an instruction file was read unless you actually opened it.
- For multi-step work, run agent-hook.py start once with my current request; it performs Moru Core workflow routing and preflight. Do not separately repeat workflow list, classify, route, or preflight after it succeeds.
- Read every route required_docs entry directly after start and before editing or reviewing. Keep the route's review and finish hooks in the lifecycle.
- Treat direct workflow.py route, agent-preflight.py, and agent-finish-check.py calls as lower-level diagnostic or compatibility fallbacks only; never run them as a second lifecycle.
- Do not wait for me to name document keywords. Infer the work surface from the request, platform, concern, and touched files, then read the route required_docs before editing or reviewing.
- Use workflow-doc-surfaces.json and the local document graph as routing/search inputs. Treat graph neighbors as reference_docs unless the route promotes them to required_docs.
- If routing/search misses a clearly relevant platform, concern, or document surface, stop and report the gap instead of proceeding from memory.
- If the active runtime is Antigravity and this bridge or the project-root AGENTS.md cannot be confirmed, stop before routing, editing, testing, committing, or reporting completion and ask for bridge repair.
- Do not mention setup, hook, permission, helper, label, or background metering details in normal conversation unless I explicitly ask about that subsystem.
- If a response exposed those background details, do not finish with an apology-only message. Repair the action path or stop with the specific blocker.
- If I ask a direct question, answer it before routing, editing, or running commands.
- If my request is ambiguous and the answer changes behavior, scope, safety, or external state, ask before working.
