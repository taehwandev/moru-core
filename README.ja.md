# Moru Core (モル・コア)

[日本語](README.ja.md) · [English](README.md) · [한국어](README.ko.md) · [简体中文](README.zh-CN.md)

Moru Coreは、AIコーディングエージェントの作業手順と「完了（Done）」の基準を揃えるための共通ルールです。一度つなぐだけで、Claude Code、Codex、Antigravityなどのエージェントがどのリポジトリでも**その作業に必要な文書だけを読み、通過済みのテスト結果を引き継ぎ、テストと安全チェックが通ったときだけ「完了」と報告**するようになります。プロジェクト固有のルールは各リポジトリに短く記述し、常にプロジェクト側のルールが優先されます。

- リポジトリ: <https://github.com/taehwandev/moru-core>
- ウェブサイト: <https://getmoru.com/core> · [なぜMoru Coreか・5ヶ月間の実測レポート](https://getmoru.com/report)
- リリース: <https://github.com/taehwandev/moru-core/releases> · リリースノートは [`.github/release-notes/`](.github/release-notes/)

エージェントが直接参照する基準は [AGENTS.md](AGENTS.md) と英語の共通ドキュメントです。本ページは開発者向けの日本語ガイドです。

## 主な特徴

- **いつものツールをそのまま使える**: Claude Code、Codex、Antigravityを乗り換える必要はなく、短い接続ブロックを足すだけでそのまま動きます。
- **今の作業に必要な文書だけを読む**: 20個のルールファイルを毎回丸ごと読み込むのではなく、今回の作業に必要な数ファイルだけを選んで読みます。
- **口先だけでなく、実際に確認してから完了にする**: テスト、コードレビュー、安全チェックを実際に通過した記録（JSON）が揃うまで作業を完了にしません。
- **プロジェクト固有の設定はリポジトリに残す**: ビルド・テストコマンドやディレクトリ構成、秘密情報などは各リポジトリ側で管理します。
- **編集前後の安全チェックを標準搭載**: [VibeGuard](https://vibeguard.thdev.app/)（Moru Guard）がMoru Coreのルールを使って、秘密鍵の漏洩や危険な操作を事前に防ぎます。

ランタイム構成: ランチャー `~/.moru/bin/moru-hook`、環境変数 `MORU_*`、ドキュメント内プレースホルダー `<MORU_ROOT>`/`<MORU_LAUNCHER>`、ローカル記録 `.moru`、エージェントロール `moru_explorer`/`moru_worker`/`moru_reviewer`。

## なぜ Moru Core なのか（他方式との違い＆5ヶ月間の実測結果）

![Moru Core 5ヶ月間の実測データ＆ツール比較](docs/assets/moru-core-telemetry.svg)

コーディングエージェントに日々の開発を任せていると、すぐに3つの問題にぶつかります。
1. **`CLAUDE.md` にルールを書き足すほど、毎ターンのトークン消費が膨らむ。** ちょっとした質問をするだけでも、コミット規約やリリース手順まで毎回読み込まれてしまいます。
2. **セッションをまたぐと同じテストや同じ失敗を繰り返す。** さっき通ったばかりのテストを最初からやり直したり、先週調べたバグの原因を忘れて同じ場所を何度も調べたりします。
3. **テストが落ちているのに「完了しました」と報告される。** あるいは1つのファイルに900行のコードを詰め込んで、人間がレビューしづらい変更を作ってしまいます。

Moru Coreは、使い慣れたCLIの内部でこの3つの問題を解決します。

| 比較のポイント | **Moru Core (いつものCLIにつなぐルール)** | 標準CLIのみ (素の Claude Code / Codex) | 巨大なルールブック＆スキル集 (長大な `CLAUDE.md` / `Superpowers`) | 独立型エージェントアプリ (例: Hermes Agent) |
| --- | --- | --- | --- | --- |
| **ツールの乗り換えが必要？** | **✓ 使い慣れたClaude Code・Codex・AGYの中でそのまま動く** | ✓ 今のCLIをそのまま使用 | △ 今のCLI＋巨大なルールファイルや初期プロンプトを追加 | △ 専用のエージェント実行環境・ターミナルへの切り替えが必要 |
| **必要なルールの探し方** | **✓ Wikimap（LLMトークン0・0.1秒のセクション検索）** により、モデルが手探りする前に必要な文書（平均 `4.15` 件）だけを即座に特定（全件読込 `20.45` 件比 **-79.7%**） | △ 基本ファイル1つだけ読み、残りは手探りで探す | ✕ 20個以上のルールを毎ターン全部読む（スキル集は都度呼び出し） | △ スキル一覧（約 `3K`）を毎回プロンプトに載せ、スキル閲覧や過去チャット検索・要約に追加のLLMターンとトークンを消費 |
| **ちょっとした質問** *(「なぜこのAPIだけ遅い？」)* | **✓ 手続きなしで即答**: ブランチ作成やチェック手順を省き、関連コードだけ読んで即答（ファイルの書き換えも自動ブロック） | △ 自分でプラン/読み取り専用モードに切り替える必要がある | ✕ 質問だけでもコミットやリリースのルールまで一緒に読み込まれる | △ 初期メモリを載せたまま通常のエージェントセッションを実行 |
| **長く使ってもルールが荒れない理由** | **✓ テスト検証済みの改善＋期限付きメモ**: 実際のテスト（`repair-verify`）を通過した改善だけを全26リポジトリに反映し、プロジェクトメモは見直し期限（`--review-on`）と適用条件付きで最大3件のみ参照（3週間でステップ数 **-79.5%**） | ✕ 人間が手で `CLAUDE.md` を書き直すしかない | ✕ 固定されたMarkdownのため自動で学ばず、有効期限の管理もない | △ テスト検証や有効期限なしでスキル・メモリを自動書き換えするため、誤った対処法がプロンプトに残り続ける |
| **続きの作業やコミット時** | **✓ コードが変わっていなければ通過済みテストを引き継ぐ**（続きの作業でステップ数 **-54.4%**、コミット時のトークン **-85.6%** 削減） | ✕ 直前にどのテストが通ったか引き継げない | ✕ プロンプトのチェックリストを最初からやり直す | ✕ 過去の会話は検索できるが、コードが変更されていないかは判定できない |
| **いつ「完了（Done）」になる？** | **✓ 確認が通るまで完了にしない**: テスト通過、新規ファイル追加 `300行` 以内、安全チェック通過を確認してから完了にする | ✕ 自作スクリプトを組まない限りエージェントの自己申告で完了 | △ プロンプトでのお願いベースのため、会話が長くなると飛ばされやすい | △ サンドボックスやチャット連携は強力だが、完了判定はモデル任せ |

### 5ヶ月間・26個のリポジトリでの実測結果（4,984コミット・419,857ステップ）

2026年5月から10月にかけて、26個のリポジトリで行ったすべての開発作業（`419,857` ステップ、Codexスレッド `1,207` 件、Moru Core実行 `584` 件）の記録です。同じモデルを使いながら、Moru Coreの仕組みを整える前後を比較しました。

- **作業1回あたりに読むルール文書が -79.7% 減少**（7月に全ルールを読んでいた頃は平均 `20.45` 件 → 10月は必要な平均 `4.15` 件のみ）。
- **Gitコミット1件あたりのステップ数が -60.7% 減少**（`150.7` ステップ → `59.2` ステップ）、**1日あたりのコミット数は +122.4% 増加**（アクティブなリポジトリ1つあたりの日次コミットが `2.68` → `3.86` 件へと **+44.0%** 向上）。
- **変更ファイル1つあたりのトークン使用量が -78.1% 減少**（7月の `432.5K` → 10月の `94.6K`。コミット1件あたりのトークンも7月の `3.07M` から10月の `1.63M` へと **-46.9%** 減少）。
- **Codexの1スレッドあたりトークン中央値が -93.8% 減少**（`20.28M` → `1.25M`、最も重かった上位10%も `146.1M` → `17.9M` に縮小）。
- **まったく同じモデル（`claude-opus-5-5`）での9月 vs. 10月比較**:
  - 作業1回あたりのステップ数（中央値）が **`591.0ステップ → 35.5ステップ`（-94.0%）** に、トークン使用量が **`33.47M → 0.41M`（-98.8%）** に減少しました。
  - `gpt-6-sol` でも作業あたりのステップ数が **`855.0ステップ → 174.5ステップ`（-79.6%）** に減少しました。
  - 10月の作業で比較すると、直前の作業を引き継いだ場合は新規作業に比べてステップ数が **-54.4%（`45.0 → 20.5ステップ`）** 少なく、確認済みの変更をコミットする作業ではトークンが **-85.6%（`2.02M → 0.29M`）** 少なく済みました。

### なぜ Moru Core は使うほど速くなるのか（複利効果）

固定されたルールファイルは昨日の失敗から学べません。かといってエージェントに見直し期限なしで勝手にスキルを書き換えさせると、古いルールが溜まって逆効果になります。Moru Coreには**使うほど無駄が減って速くなる3つの仕組み**があります。

1. **見直し期限付きの短いプロジェクトメモ（作業ごとに最大3件まで）**: コードを読むだけでは分かりにくいバグの原因や注意点を突き止めたとき、適用条件と**見直し期限（`--review-on`）**を付けた短いメモ（`project-memory`）を保存します。次回同じプロジェクトで作業するときは、関連する有効なメモを**最大3件だけ**呼び出すため、プロンプトを膨らませずに同じ回り道を防ぎます。
2. **1つのプロジェクトで直した失敗が、26個すべてのプロジェクトにすぐ効く（`repair-verify`）**: よく起きるつまずきやチェック失敗（5ヶ月間で `337` 件検出 → `10` 件採用 → `6` 件を共通ルール化）は、共通ルールやチェック処理を一度直して検証するだけで、つながっている**全26リポジトリの次の作業からすぐに反映**されます。
3. **実際の結果：新規の作業でも3週間でステップ数が 79.5% 減少**: 引き継ぎ作業ではなく**ゼロから始める新規（`fresh`）作業**だけを同じモデル（`claude-opus-5-5`）で比べても、プロジェクトメモと共通の改善が溜まるにつれて、作業あたりのステップ数（中央値）が **10月第1週 `112.0ステップ` → 第2週 `48.5ステップ`（-56.7%）→ 第3週 `23.0ステップ`（-79.5%）** と毎週着実に短くなりました。

手元のMacに記録された月別・週別の効率推移は、いつでも以下のコマンドで確認できます（プロンプト本文やファイルパスは一切出力されません）：

```bash
python3 scripts/agent-os-status.py --efficiency-trends --all-projects --month 2026-10
```

## クイックスタート

すでにマシン上にMoru Coreがある場合や、リポジトリにサブモジュールがある場合はそれをそのまま使います。新しくクローンする前には必ずユーザーに確認します。

```bash
git clone https://github.com/taehwandev/moru-core.git ~/.moru/core   # 個人用の共有インストール（初回のみ）
python3 ~/.moru/core/scripts/setup-agent-hooks.py                     # エージェント接続の設定
<MORU_LAUNCHER> workflow validate
<MORU_LAUNCHER> doctor --project <対象リポジトリ>                      # 状態チェック（読み取り専用）
```

### `skills.sh`（`npx skills`）からのインストール

[skills.sh](https://www.skills.sh/taehwandev/moru-core) を使って、Moru Core 全体のブートストラップスクリプトや、単体でも使える代表的な14個の汎用スキル（`human-authored-writing`、`figma-handoff`、`ambiguity-gate`、`code-review` など）を直接インストールすることもできます：

```bash
# Moru Core 全体のブートストラップ＆ルーティングスキルを接続
npx skills add taehwandev/moru-core --skill moru-core

# 公開されている15個の代表スキル一覧を確認・個別インストール
npx skills add taehwandev/moru-core --list
npx skills add taehwandev/moru-core --skill human-authored-writing
```

チームで同じバージョンを固定したい場合は、リポジトリ管理者の承認を得てサブモジュールとして追加できます：

```bash
git submodule add https://github.com/taehwandev/moru-core.git .agents/moru-core
```

アップデートは作業の合間に `git pull --ff-only` と `workflow validate` で行います。

## プロジェクトへのつなぎ方

1. プロジェクトにすでにある `AGENTS.md`、`CLAUDE.md`、`CODEX.md` などの指示ファイルを先に確認します。
2. [`templates/repo-agents-routing.md`](templates/repo-agents-routing.md) の短い案内ブロックをエージェントが読むファイル（優先は `AGENTS.md`）に追記します。
3. コミットするファイルには個人の絶対パスを書かず、`<MORU_ROOT>`、`${MORU_HOME}`、`.agents/moru-core` などの共通表記を使います。
4. VibeGuard（Moru Guard）のルールソースとしてMoru Coreを指定します。

自分で設定する代わりにAIエージェントに任せる場合は、プロジェクト内でエージェントを開いて次の文を貼り付けてください：

```text
このプロジェクトにMoru Coreを適用してください: https://github.com/taehwandev/moru-core
すでにローカルにMoru Coreがあればそれを再利用し、新しくダウンロードする場合は先に確認してください。
このリポジトリの既存の指示ファイルとVibeGuard設定を先に読み、書き換える前に確認してください。
AGENTS.mdに短いルーティングブロックを追加し、リポジトリ固有のルールはそのまま残してください。
```

完全なテンプレートは [`templates/apply-moru-request.md`](templates/apply-moru-request.md) にあります。

## 作業の流れ

コードを読むだけの質問には、ワークフローを起動せず関連コードを読んでそのまま答えます。
ファイルを変更する作業は、ランチャーを通して以下の流れで進みます：

```bash
<MORU_LAUNCHER> start --project <対象リポジトリ> --rules <MORU_ROOT> \
  --command <作業ルート> --request "<ユーザー要求>" \
  --intent <短い分類名> --target-summary "<作業対象の要約>"
```

1. **開始（`start`）**: 依頼内容に合った作業ルート（`small-change`、`bugfix`、`feature`、`docs` など）と権限範囲を決めます。
2. **必要な文書だけ読む**: その作業に必要な文書（`required_docs`）だけを読みます。
3. **作業とテスト記録（`gate-batch`）**: コードを変更し、テスト結果を記録します。`<MORU_LAUNCHER> next` を実行すれば、いつでも次の手順とコマンドを確認できます。
4. **レビュー（`review`）と完了確認（`finish`）**: 変更サイズ（新規・拡張ファイル300行以内）や安全チェックを確認し、必要なチェックがすべて通ってから完了報告やコミットを行います。

チェック結果は `🐱🟢 SUCCESS` または `🐱🔴 FAIL` で表示されます。作業の続きを行うときは `start --continue-from <前回のrun id>` で確認結果を引き継ぎます。判明した原因は `project-memory` に、残りのタスクは `work-cards` に残ります（詳細: [docs/project-memory.md](docs/project-memory.md)）。

## 連携する Moru エコシステムツール

- **[VibeGuard](https://vibeguard.thdev.app/)（Moru Guard）**: Moru Coreのルールを基準に、編集前と完了前に秘密鍵の漏洩や危険な変更をチェックします。
- **[Wikimap](https://github.com/dhha22/wikimap)**: LLMトークンを一切使わず、0.1秒未満で今回の作業に必要なルール文書だけを特定します。
- **[Spill](https://getmoru.com/spill)**: Mac上でコーディングエージェントのトークン消費とセッション履歴を可視化し、セットアップ時にタスクラベルが自動連携されます。
- **[Moru Artemis (`moru-artemis`)](https://github.com/taehwandev/moru-artemis)**: Claude Code・Codex・Antigravityから接続中のAndroid実機やエミュレータをMCP経由で直接操作できるオープンソースアダプター（`google/artemis` のApache-2.0フォーク）です。追加のLLM APIキー不要で動作し、生XML比 **-96.4%軽量なコンパクトUIツリー取得（約 `0.19秒`）**、画面安定待機（`wait_for_stable`）、スクロール終端・移動量の自動検出を備えています。
